# /session-start — 会话开场审查

目标：**每 5 分钟给出"项目现在在哪、今天该做什么"**。

## 流程

```
[用户：审查进度 / 开场]
   ↓
[Phase 1: git 状态] git log --oneline -10 + git status --short + 当前分支
   ↓
[Phase 2: 读配置] PROJECT_INDEX.md（路径/约定）+ ROADMAP 当前里程碑与优先级
   ↓
[Phase 3: 一致性核对] 抽查关键代码文件 vs 文档勾选状态（发现"文档落后于代码"或"标完成但未接线"）
   ↓
[Phase 4: 输出] 进度报告 + 今日建议（含待决策项提醒）
```

## 输出格式

```
# 📋 进度报告 YYYY-MM-DD

## 里程碑状态
- 当前：{{MILESTONE}} | 完成度：{{X}}/{{N}} 项

## 上次会话以来
- 提交：{{hash}} {{message}}（+N 文件）
- 未提交工作：N 个文件（列出关键）

## 文档 vs 代码一致性
- ⚠️ 发现差异：{{差异描述}}

## 今日建议（按优先级）
1. {{P0 事项}}
2. {{P1 事项}}

## 待决策提醒
- {{决策项}}
```

## 规则

- **先看 git 再读文档**：git 是事实，文档是意图，差异就是工作。
- 差异不要悄悄改文档——列出来，让用户确认是"文档错"还是"代码错"。
- 发现未提交的大堆工作（>10 文件）→ 提醒先提交防丢失（见 /commit）。
