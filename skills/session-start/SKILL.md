# /session-start — 会话开场审查

目标：**每 5 分钟给出"项目现在在哪、今天该做什么"**。

## 流程

```
[用户：审查进度 / 开场]
   ↓
[Phase 1: git 状态] git log --oneline -10 + git status --short + 当前分支
   ↓
[Phase 2: 读配置] PROJECT_INDEX.md（路径/约定）+ ROADMAP 当前里程碑与优先级
   │  ⤷ 带硬截止/时间盒的文档：按当前时刻**重算并原地改掉过期数字**（事实核实.md §11）
   ↓
[Phase 3: 一致性核对] 抽查关键代码文件 vs 文档勾选状态（发现"文档落后于代码"或"标完成但未接线"）
   │  ⤷ 对文档里每条"未完成/待确认"跑一次最便宜的事实检查（grep/看文件/看引用），别照抄（事实核实.md §9）
   ↓
[Phase 4: 输出] 进度报告 + 今日建议（含待决策项提醒）
```

## 判据（遇到对应情形先读，别凭印象）

- 需求含糊、要不要砍范围、要给用户写"点哪里"的步骤 → `shared-references/需求与范围.md`
- 汇报 / 提交信息 / 文档状态该不该信 → `shared-references/事实核实.md`
- 多会话并发改文档、合并冲突、推送 → `shared-references/协作与交付.md`
- 这条信息该写进哪份文档 → `shared-references/doc-roles.md`

## 输出格式

```
# 📋 进度报告 YYYY-MM-DD

## 里程碑状态
- 当前：{{MILESTONE}} | 完成度：{{X}}/{{N}} 项

## 上次会话以来
- 提交：{{hash}} {{message}}（+N 文件）
- 未提交工作：N 个文件（列出关键）

## 文档 vs 代码一致性
- ⚠️ 发现差异：{{差异描述}}

## 今日建议（按优先级）
1. {{P0 事项}}
2. {{P1 事项}}

## 待决策提醒
- {{决策项}}
```

## 规则

- **先看 git 再读文档**：git 是事实，文档是意图，差异就是工作。
- 差异不要悄悄改文档——列出来，让用户确认是"文档错"还是"代码错"。
- 发现未提交的大堆工作（>10 文件）→ 提醒先提交防丢失（见 /commit）。
- **多会话共用同一工作区时**：改文档前先 `git log`/`git status` 核对，写前重读、写完回读；发现文档正被并发写就提醒用户只留一个窗口（`协作与交付.md` §1）。
- 用户问"**我应该点哪里 / 具体怎么操作**"时，必须先**重读当前仓库**（主场景 + 目标场景 + `git status`），不能拿几轮前的读取结果作答（`需求与范围.md` §5）。
- 报告里区分标注「**实测**」与「**推断**」——推断不得写成结论（`事实核实.md` §7）。
