# /index-sync — 索引同步

目标：**PROJECT_INDEX.md 永远反映真实结构，让任何会话/任何人 10 秒定位所有管理文件**。

## 何时触发

- 新增/删除/移动了管理相关文件（文档、模板、配置）
- 新增/删除了目录（如新建 `design/`、`devlog/`）
- 仓库结构变化（如移动 .git 根、新增子仓库）
- 工作流规则变更

## 流程

```
[触发：路径/结构变更后]
   ↓
[Phase 1: 收集变更] 列出本次新增/删除/移动的文件与目录
   ↓
[Phase 2: 更新索引]
   ├─ 文件表格：增删对应行（路径 + 一句话作用）
   ├─ 目录树：保持与实际一致
   └─ 更新记录：追加 YYYY-MM-DD 条目
   ↓
[Phase 3: 提交] 索引 + 相关文档一起提交
```

## 索引模板结构（见 templates/project-index.template.md）

管理文档表 / 仓库级配置表 / 工程内配置表 / 目录树 / 工作流规则 / 更新记录

## 规则

- 索引的**作用描述一句话**，别写成长篇——它是路标不是文档本体。
- 目录树与真实结构不一致 = 索引失效，宁可删除分支也不要画错。
- 每次改动都在"更新记录"留痕，索引自己也要有历史。
