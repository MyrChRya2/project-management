# /daily-wrap — 每日收尾写日志

目标：**每天结束时，把"今天"固化成一条可检索、可复盘、可作为视频/周报素材的记录**。

## 流程

```
[用户：今天任务已结束 / 更新日志]
   ↓
[Phase 1: 读模板] {{LOG_DIR}}/TEMPLATE.md（骨架 + 提问清单）
   ↓
[Phase 2: 收集事实] git status/diff 看今天实际改了啥（代码侧事实）
   ↓
[Phase 3: 引导补充] 按模板区块逐项问用户（完成内容/决策/踩坑/下一步）；用户说"没有补充"则跳过
   ↓
[Phase 3.5: 待确认点询问] **主动列出本会话遗留的待确认/待决策项**（文档差异、未决参数、遗留问题、上次挂起事项），逐项问用户"确认 / 补充 / 忽略"；再问一句"还有没有需要补充的东西"
   ↓
[Phase 4: 生成日志] {{LOG_DIR}}/YYYY-MM-DD.md（同日多篇加 -b/-c 后缀）
   ↓
[Phase 5: 同步] 勾选 ROADMAP 完成任务；决策写入决策记录区；GDD 如有涉及同步；**如有 bug 修复 → 更新 ROADMAP「已知 Bug 跟踪」表状态（✅ 已修复 + 日期）**
   ↓
[Phase 6: 提交] 日志 + 文档改动一起提交推送（不混入无关代码）
```

## 命名规则

- 当日首篇：`YYYY-MM-DD.md`
- 同日追加：`YYYY-MM-DD-b.md`、`YYYY-MM-DD-c.md` …（每个独立主题一篇）

## 模板区块（见 templates/devlog.template.md）

摘要 / 完成内容 / 决策与理由 / 踩坑 / 文件变更 / 进度与下一步 / 阻塞与待决策 / 其他（素材·灵感·备忘）

## 规则

- **事实优先**：先看 git diff 再问用户——用户常忘自己改了什么，diff 是提醒。
- 用户明确说"没有补充"时，**直接生成**，不要反复追问同一字段。
- **收尾必问**（Phase 3.5）：主动列出待确认/待决策项，逐项询问"确认 / 补充 / 忽略"，最后再问一次"还有没有需要补充的东西"。这是用户 2026-08-21 明确要求的收尾环节。
- **日志职责专属**：更新 devlog 是收尾工作的固定环节；**只有项目管理 agent 需要更新日志**（除非用户特殊要求）——自媒体/辅助编程会话默认不写日志。
- 失败尝试也要记（今天试了什么效果不好、为什么、下一步方向）——这是复盘和 R1 类素材的富矿。
- 日志生成后立即提交推送，避免积压。
