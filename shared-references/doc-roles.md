# 文档职责划分（Doc Roles）

单人开发 + AI 辅助时，文档必须**单点职责、互相引用、不重复**。多份文档写同一件事 = 必然漂移。

| 文档 | 职责 | 回答的问题 | 更新时机 |
|------|------|-----------|---------|
| **GDD**（设计文档） | 设计的"宪法"：玩法、系统设计、架构、待决策清单 | "这游戏是什么、怎么设计" | 设计变更、决策拍板 |
| **ROADMAP**（路线图） | 执行的"计划"：里程碑、任务清单、完成标准、优先级、决策记录、**Bug 跟踪表** | "现在该做什么、何时算完、有哪些 bug" | 任务完成/新增/优先级变动、决策、bug 登记与修复 |
| **devlog**（开发日志） | 时间的"流水账"：每天做了什么、踩了什么坑、下一步 | "那天发生了什么" | 每天收尾 |
| **PROJECT_INDEX**（索引） | 空间的"地图"：文件在哪、工作流约定 | "哪个文件管什么" | 路径/结构/规则变更 |

## 铁律

1. **devlog 是唯一允许"追加流水账"的地方**；GDD/ROADMAP 只保留当前生效状态，不写过程。
2. **决策的双写**：方向性决策必须同时落在 devlog（当天）+ ROADMAP 决策记录区（长期）——缺一个就会"文档失忆"。
3. **勾选同步**：ROADMAP 任务完成时，立即勾选并附一句依据（如"见 devlog 2026-08-17-c"），让文档可追溯。
4. **索引先行**：新建任何管理文件前，先想它在索引里怎么描述——描述不出来的结构就是多余的。
5. **清单编号是对外接口**：文档里的条目编号，用户会直接拿来派活（"先解决一下 XX #2"）→ 编号**只往后排、不改号**；状态列必须实时；收到编号指令**先读那一行原文**（归属、完成标准、前置依赖都在那一行），别凭记忆作答。（Jam L84，详见 `需求与范围.md` §7）
6. **"不入库"不等于"不用登记"**：本机私有资产（离线知识库、工具链落点、团队信箱）虽不进 Git，也要在索引里登记**落点 + 用法**并标清"不入 Git"——否则项目搁置 / 换机后找不到它。
