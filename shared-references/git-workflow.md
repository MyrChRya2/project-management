# Git 工作流约定（单人开发）

目标：**历史可读、可回退、可 blame；不因"单人"就放松纪律**。

## 分支

- `main` 是唯一长期分支，始终可发布。
- 功能开发：`feature/<name>` 分支，完成后 fast-forward 合并入 main 并删除。
- 实验/备份：`backup/<name>` **标签**归档（`git tag backup/xxx`），不长期保留分支。
- 分支名拼写要准确（`feature` 不是 `featrue`），改名用 `git branch -m`。

## 提交

- 小步原子提交（见 /commit 的 type 约定）。
- **不盲 `git add -A`**：先 `git status`，分拣文件，防止误提交无关工作流的数据。
- 提交信息中文内容用英文 type 前缀，正文简洁。

## 多会话协作（同一工作区多个 AI 会话）

- 每个会话只提交自己负责的文件；其他会话的未提交工作保持原样。
- push 前 `git status --short` 确认；push 失败时本地提交保留，由用户手动推送。
- 重写历史（force push）只在"刚推送的错误提交"场景使用 `--force-with-lease`，且需用户明确确认。

## 仓库结构

- **仓库根 = 项目根**（不是引擎目录），让文档/美术源文件/代码全部纳入版本控制。
- 文档与源文件（如 Aseprite）必须入库——无版本控制 = 无备份。
- 敏感数据（凭证、登录态）用 `.gitignore` 排除，绝不入库。
